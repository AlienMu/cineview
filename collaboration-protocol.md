# Collaboration protocol

Read this file when a task has a material ambiguity about its goal, scope, deliverable, execution method, or authorization; when consequential choices would change the result; or before destructive or irreversible actions, changes to global behavior, work on real external targets, or high-cost changes.

1. Establish what is already known from the user's current and earlier instructions, repository guidance, and current source. Do not ask the user to repeat a settled decision.
2. Complete reversible investigation and prepare a concrete, reviewable proposal before requesting a decision or approval. Do not use a question as a substitute for inspecting the project.
3. Identify the smallest decision that actually changes the result. State the recommended choice and its key reason. Ask one clear question at a time when the answer is required. Continue independent work that does not depend on the answer.
4. Once the user resolves the decision, record it in the local task flow when the task spans files, then proceed. Do not reopen it without new evidence or a conflicting instruction.
5. A clear, local instruction does not require confirmation merely because it writes files or changes the environment. Follow explicit user authorization before a destructive, irreversible, or real external action.
6. When a proposed approach has a false premise or substantial hidden cost, explain the most important issue and recommend the better path. Resolve technical uncertainty against current code, types, tests, and observed behavior.
