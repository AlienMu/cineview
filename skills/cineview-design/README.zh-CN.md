# Cineview 设计参考

这是一份写给 AI 看的技能，用来帮你用 Cineview 做落地页。它不会一拿到素材就动手，而是先和你沟通：
- 先问页面主要在什么设备上看：手机、电脑，还是两端都要；
- 弄清页面要做什么、给谁看，以及用整页拖动还是整页滚动（拖动只用于手机，滚动在哪里都能用）；
- 给出两三个方向，建议做几幕；
- 逐幕讨论每一幕讲什么、读者看到什么、用哪些素材、还缺什么，拖动页还要定每一幕怎么切换进来；
- 最后整理成分镜表和素材清单。你明确说「好」之后，它才开始制作。

最后这一条是整个技能里唯一一条强制规则：你没有在自己的消息里明确同意分镜之前，AI 不写任何页面文件。沉默、取消确认框、只同意其中一幕，都不算同意。

其余文件是它给建议时用的设计思路和参考，包括视觉风格与搭配、41 种动效参考各自表达什么、文字和画面的几种关系、幕与幕之间怎么衔接、拖动模式怎么设计、手机上要注意什么。这些都写成「选项加理由」，不是模板。例子里的字体和颜色都是变量，换成你自己的品牌、素材和喜好，做出来的页面就像你自己的产品。

技能按 npm 上的 cineview 2（`cv-*` 元素写法）编写。1.0.x 是另一套 React 写法，不要把两套例子混在一起用。

## 怎么用

- **Claude Code**：把整个 `cineview-design` 目录复制到项目的 `.claude/skills/` 下，Claude 会在相关任务里读取它。
- **Cursor、Codex 等其他工具**：先让 AI 读 `skills/cineview-design/SKILL.md` 和 `conversation.md`，再按需读其他文件。
- **直接对话**：把 `SKILL.md`、`conversation.md` 和要用到的几份文件一起贴给 AI。

然后像平时一样说你想做什么，比如「我想给我的摄影展做个页面，有八张照片」。AI 会一次只问一个问题，每个问题都附上它的建议和理由。同意就回「好」，不同意就直接改。你的产品、素材和喜好说得越具体，做出来的页面越像你自己的。

## 里面有什么

| 文件 | 内容 |
|---|---|
| `SKILL.md` | 先讨论再制作的规则、文件目录、框架本身的几条规律 |
| `conversation.md` | 怎么和你沟通：设备、页面模式、方向和幕数、逐幕内容和切换、分镜表和素材清单（先读这份） |
| `sources.md` | 从产品本身找颜色、动作和母题的提问清单 |
| `styles.md` | 16 种视觉风格：气质从哪来，可选的字体搭配，示例配色和从素材取色的方法，适合什么、容易出什么问题 |
| `pairings.md` | 风格和动效、模式、素材怎么搭配，两种风格怎么混搭，哪些组合容易冲突 |
| `motion.md` | 41 种设计参考：各自表达什么、强弱怎么调、适合哪些模式、和什么冲突 |
| `relationships.md` | 文字和画面的八种关系，以及各自在滚动、停留场景、拖动和手机上的表现 |
| `handovers.md` | 幕与幕之间怎么衔接（滚动和拖动），以及用视频做转场 |
| `drag.md` | 拖动模式：两幕同时在动是怎么回事、时间怎么算、首屏和最后一幕、无障碍、在电脑上的表现、刷新后回到同一幕 |
| `phone.md` | 手机设计：一屏放多少、单位和字号、竖拍素材、性能、App 内置浏览器，以及两端都要时的两种做法 |
| `images.md`、`video.md`、`type.md`、`line-art.md` | 素材：想让它表达什么就用什么处理，以及怎么准备素材 |
| `colour.md` | 从素材取色、随场景或滚动变化的颜色、可读性 |
| `ranges.md` | 可读性、节奏和拖动的常见数值范围 |
| `framework.md` | 框架速查：元素、属性、效果预设、时间来源、时间规则、事件、脚本接口 |
| `drawing.md` | 用时间线驱动自己画的 Canvas、WebGL、SVG |
| `checks.md` | 双语切换、刷新不闪、滚动页和拖动页的检测方法 |
