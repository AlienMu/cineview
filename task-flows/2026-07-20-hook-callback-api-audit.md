# CineView Hook and Callback API Audit

## Goal

Audit every externally observable hook, callback, and ref method for trigger timing, event loss,
debounce/throttle/RAF boundaries, stale closures, duplicate delivery, and mode-specific consistency.

## Callback Frequency Contract

### Realtime / sampled callbacks

- `onDragProgress`: publish every accepted drag sample in order; may be frame-sampled but must deliver
  the latest value and the terminal `0`/commit sample. It must not use trailing debounce.
- `onZoneProgress`: publish every changed zone progress snapshot generated by the scroll owner; no
  debounce, no lost boundary `0` or `1`, no duplicate unchanged values.
- `onLoadProgress`: publish each monotonic resource-settlement step including terminal `100`; background
  loading must not suppress or reorder the priority completion signal.
- `Scene.callbacks.onVisibilityChange` / `onSceneVisibilityChange`: publish meaningful visibility/progress
  changes from the active owner; avoid duplicate identical payloads while preserving boundary changes.

### Semantic boundary callbacks

- `onDragStart`: once per accepted gesture.
- `onDragCommit`: once per committed gesture or successful `ref.goToScene` in drag mode.
- `onDragCancel`: once per rejected/bounced gesture.
- `onZoneEnter` / `onZoneLeave`: once per actual active-boundary crossing.
- `onSceneWillChange`: once before a valid scene transition.
- `onSceneDidChange`: once at render commit, independent of element-track completion.

### Lifecycle / error callbacks

- `onReady`: once per mounted CineView instance; callback identity, mode progress, performance toggles,
  and ref navigation must not retrigger it.
- `onError`: once per distinct runtime error occurrence; registry validation may batch diagnostics but
  must not swallow production errors or emit duplicates for one snapshot.

### Public hooks and refs

- Exported hooks must not expose stale callback closures or internal debounced state as if current.
- `goToScene`, `goToZone`, `refreshLayout`, `preload`, `getCurrentScene`, and
  `getPerformanceMetrics` must be callable with fresh state and deterministic callback ordering.

## Initial Questions

- Does `onDragProgress` receive the latest sample before `onDragCommit`/`onDragCancel`, including fast
  pointer bursts inside one frame?
- Does `onZoneProgress` emit both exact boundaries when a large delta is anti-skip clamped?
- Can `onLoadProgress` emit stale values after callback replacement or component unmount?
- Are Scene visibility callbacks duplicated because grouped and legacy callback paths are both present?
- Does resize debounce delay only layout refresh, or does it accidentally delay a public callback/ref read?
- Do callback identity changes retrigger lifecycle effects or leave handlers with stale closures?

## Findings And Fixes

- Drag progress was published from a React state effect, so batched pointer samples collapsed and
  equal-magnitude direction reversals were deduplicated. Publication now happens at the drag runtime
  input boundary, preserving signed samples and callback order.
- Drag cancel was previously coupled to `isDragging=false`, although the engine emits that signal before
  a successful settle commit. Cancel now belongs to reset/bounce outcomes; successful settle emits commit
  only. Bounce cancel retains the release-point progress and direction.
- Scene visibility callback identity changes could re-emit an identical payload. Callback refs now update
  independently from the visibility-change effect, so only meaningful visibility/progress changes publish.
- Media preload rejection could call `onError` after unmount/reset because the error path ran before the
  run-id guard. Error publication now checks the active preload run.
- Scroll `onZoneProgress` has no debounce; unchanged zone snapshots are skipped and exact boundaries are
  retained by the scroll owner's clamped snapshots. Existing boundary/re-entry suites cover this path.

## Remaining Limitations

- Internal hooks are not public exports from `src/index.ts`; the public hook-like surface is the ref API.
- Independent browser lane completed `http://127.0.0.1:3000/#/drag`: successful commit had no cancel,
  rejected bounce had one cancel, continuous and reverse gestures remained visually stable. The example
  page does not render callback payloads, so callback payload/cardinality remains covered by Jest tests.

## Ref API Follow-up

- Drag `onReady` previously depended on an object ref being present, so callback refs received no ready
  event and changing ref identity could retrigger the mount effect. It now receives a stable runtime API
  exactly once regardless of ref form.
- Drag ref commands now read current scene/actions/preload queues through refs, so an API retained from
  `onReady` remains fresh instead of closing over the mount render.
- Scroll `onReady(api).getCurrentScene()` previously closed over the initial active scene. It now reads
  `activeSceneIndexRef.current` and remains current after native scrolling.
- Follow-up verification: 120/120 targeted ref tests passed and `pnpm type-check` passed.
- Clarification after drag-rerender reproduction: `callbacks.onReady` remains one-shot. An inline React
  callback ref such as `ref={(api) => handleReady(api)}` is a different mechanism; when the parent
  rerenders on drag progress, React detaches the old ref and attaches the new function, so that ref
  callback can run for every drag-driven parent render. Consumers requiring one-shot readiness must use
  `callbacks.onReady`; use an object ref or memoized `useCallback` for the React `ref` prop.
