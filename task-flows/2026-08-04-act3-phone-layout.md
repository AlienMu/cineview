# 第三幕手机版布局（390 宽可读）— 2026-08-04

用户裁决：**只改第三幕（局部先行）**。其余四幕维持「1440 稿等比缩小」现状（D8 ② 待专项）。
目标形态（用户选定的 mockup）：2 列 × 3 行、每块约 170×217 screen px、字号约 15px 可读。

---

## 根因（已实测，不是猜测）

- `config.size=1440` +「认宽不认高」⇒ `--cineview-unit = vw/1440`；390 宽时 u=0.2708。
- `HomeSceneCanvas` 声明 1440×900 ⇒ 画布实际 **390×244**，占 844 视口高的 29%。
- 六块的定位容器是 `.capability-full.act3-dolly`（`position:relative`，填满画布）——
  实测 `offsetParent` 高 244；把画布高改到 844 后六块整体下移 300 = (844−244)/2，
  **画布高就是可用的杠杆**，且 scene 本身已有 844 的空间。
- 字小的真因不是「窄视口」而是**设计 px 太小**：panel 字号 15 设计 px → 4~5.5 screen px；
  第一幕标题 32 设计 px → 8.7px。同一把尺子下，要 screen 可读就必须**放大设计 px**。

---

## 方案（框架原生，不用 !important）

`Container` 本就有 `height` 便捷属性（`Container.tsx:40` 走 `context.convert`）。
故不去覆盖行内样式，而是**把高度作为参数传进去**。

1. **新 hook**（site 侧，resize-only，非每帧）：`useDesignCanvasHeight()` →
   `{ phone: boolean, designH: number }`。
   - `phone = matchMedia('(max-width: 600px)').matches`
   - `designH = phone ? 1440 * vh / vw : 900`（即手机上画布 = 100vh 的设计 px 等价值）
   - 只订阅 `resize` + mql `change`，不进每帧热路径（CLAUDE.md 自检 4）。
   - 站内已有 matchMedia 先例（`TimecodeAxis.tsx:21`、`CapabilityScene.tsx:211`）。
2. **`HomeSceneCanvas` 加可选 `height`**（默认 900），仅第三幕在 `HomePage` 传 `designH`。
   其余四幕不传 ⇒ 行为逐字节不变。
3. **`Act3DollyScene` 按 `phone` 切布局数据**：
   - `PANELS_DESKTOP` = 现有 3×2 散落（不动，桌面已验收）。
   - `buildPhonePanels(designH)` = 2 列 × 3 行。x/w 用固定设计 px（宽是稳定轴），
     y/h 用 `designH` 的比例（高随手机宽高比变，写死会在 375×667 这类矮机型被裁）。
   - `resolvePeakScale` 增加 `canvasW/canvasH` 形参（现在读模块常量 `CANVAS_W/H`）。
     `peak` 仍是纯函数，只是多一个入参。
   - 收尾标题 y：桌面 372（`anchor:'center-x'`，y 是**距画布顶**的偏移）；
     手机 `0.842 * designH`。
4. **CSS**：`@media (max-width: 600px)` 只改 `--a3-fs` → `calc(64 * var(--cv-u))`
   （390 时 17.3px，乘 base 0.62–0.86 后渲染 10.7–14.9px 可读）。
   桌面 clamp 规则保持不动（600–960 区间已验收）。

### 手机几何（推导，非拍脑袋）

设 `H = designH`（390×844 → 3116；375×667 → 2561；428×926 → 3115）。

| 量 | 值 | 390×844 的 screen 值 |
| --- | --- | --- |
| 列 x | ±360 设计 px | ±97.5 |
| 盒宽 w | 730 设计 px | 197.7（渲染 ×base = 123–170）|
| 行 y（距中心）| `H × (−0.29, −0.05, +0.19)` | −254 / −44 / +167 |
| 盒高 h | `H × 0.26` | 219.4（渲染 ×base = 136–189）|
| 行距 | `H × 0.24` > 最大渲染高 `H × 0.224` | 无纵向重叠 ✓ |
| 首行上缘 | `−0.402H`，距画布顶 `0.098H` | 83 px（REC/slate 在 27–37，clear ✓）|
| 末行下缘 | `+0.302H`，剩 `0.198H` | 167 px（标题块实测 57 高，充裕 ✓）|
| 标题 y | `0.842H`（距顶）| 711（块底 768，画布底 844，clear 76 ✓）|

`base` 沿用现有 0.62–0.86 六档 ⇒ **渲染尺寸天然不一**（满足用户「大小不一」要求）。
横向：最大渲染半宽 314 设计 px，左块 −674..−46、右块 +46..+674，**渲染矩形不重叠** ✓
（盒矩形在中线附近有 10 设计 px 交叠，但重叠判据用渲染矩形，与桌面同）。

字号校验（会不会撑破）：盒 730×810 设计、字 64 ⇒ bar≈160、code≈115、body≈535，
chain 内容≈365 ≤ 535 ✓。手机盒的长宽比（0.9）比桌面（0.68）更竖，正好吃得下更密的字。

## 风险

1. **画布高变化是否影响 takeover 测量**：scene 仍 `height:'100vh'`，画布从 244 长到 844
   正好填满、`overflow:hidden` 不产生新滚动高；且 takeover 预算来自动画时长（1ms=1px）
   而非 DOM 高。**但必须实测**第三幕滚动跨度与接缝在改后不变（P5 覆盖）。
2. **断点两侧的突变**：600 上下会跳布局。601 宽必须仍是桌面版（P5 显式覆盖该档）。
3. **矮机型**（375×667，aspect 1.78）`H` 只有 2561，行距与盒高按比例走应仍无重叠，
   但余量最小 —— P5 必须实测该档，不能只测 390。
4. **本轮已修的三个缺陷不得回归**：字号 clamp（桌面区间）、标题/副标题 flex 排距、
   探针指针落视口中心。P5 的 wheel/overflow 双探针即覆盖。
