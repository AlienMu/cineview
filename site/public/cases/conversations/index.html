Fixed. The error you hit comes from opening the file by double-clicking, over file://: the page loads <script type="module">, and the browser blocks it before running a single line, so the console shows these two lines in red:

Access to script at 'file:///…/vendor/cineview.js' from origin 'null' has been blocked by CORS policy
Access to script at 'file:///…/page.js' from origin 'null' has been blocked by CORS policy
Failed to load resource: net::ERR_FAILED

Module scripts are always blocked under file://. It has nothing to do with the framework; it is the browser's protocol rule.

The fix

Bundle the engine from several ESM files (cineview.js plus 8 files under chunks/) into one classic IIFE script with esbuild, and load it with <script defer>:

  • New vendor/cineview.bundle.js (155.7kb, all the dynamic chunks inside)
  • index.html now loads <script defer src="vendor/cineview.bundle.js"></script>, and page.js in index.html drops type="module" too
  • The old ESM files moved to vendor/_esm-unused/; nothing was deleted (to really delete them, move them to the Trash yourself, per A2)
