# 设计 Cineview 落地页

[English](./landing-pages.md) · [简体中文](./landing-pages.zh-CN.md)

选择落地页效果前，先明确读者要理解什么，建立内容关系，再确定交互与时序。每一景都需要有用的内容和完整可读的状态。

Cineview 的设计初衷之一，是让 AI 理解这些设计决定，并向使用者提供有依据的建议。本地 2.0 的需求建议与 PRD 转换先读[AI 设计流程](./design-assistant.zh-CN.md)，再按需查询[41 条设计参考与实现入口](./lexicon.zh-CN.md)。用户可以描述目标，由 AI 推荐画面、说明取舍并核对可用能力。

设计方法适用于不同版本。现有[快速开始](./quickstart.md)、[模式](./modes.md)、[时间线](./timeline.md)和[案例](./recipes.md)对应已发布的 `cineview@1.0.1` React API。[实验中的 v2 注意事项](#实验中的-v2-注意事项)仅适用于本地 `v2/` 实现。生成代码前先确认目标版本。

## 先填写场景说明

先了解用户想做什么页面，以及有哪些内容。用户不需要知道效果名称，也不需要填写动画参数。描述不完整时，询问缺少的素材，或访客最需要记住的内容。

把 Lexicon 的 41 项作为设计参考。根据内容推荐一种合适的呈现方式，说清第一张图、操作过程中发生的变化，以及完整可读的状态。只有另一种方式会带来明显不同的阅读体验时，才提供第二种。参考数量不表示 Cineview 提供 41 个可互换预设，也不表示目标版本支持所有示例。

| 页面目标           | 起始思路                   | 方案中需要展示的内容                   |
| ------------------ | -------------------------- | -------------------------------------- |
| 介绍产品或软件功能 | 每段说明对应它描述的细节   | 图片随相关语句变化，图文保留供读者细看 |
| 解释前后变化       | 用分界控件对比已对齐的图片 | 读者调整对比时，同一主体始终对齐       |
| 展示宽幅构图       | 移动浏览素材，配合对应说明 | 图片起点、各个标注细节和实际终点       |
| 展示相关条目       | 依次介绍卡片，保留此前条目 | 出现顺序、可读标题和完整集合           |

结合[原作的内容关系](#保留原作的内容关系)完善方案。先让用户理解画面，再选择目标版本支持的 API。

实现前记录：

1. 读者的任务，以及需要记住的关键事实。
2. 实际文字、图片和视频，明确词与图、标签与对象的对应关系。
3. 静态构图，包括图片焦点、裁切和文字层级。
4. 进度来源、入场、重叠、完整阅读停留与离场。
5. 停手、反向、取消、返回此景时的行为。
6. 窄屏布局、减少动态效果、控件和浏览器验收。

每一段选择一个主要动态目的。辅助动作需要内容依据，例如标签与它解释的细节同时出现。动画完成后保留可读内容。用于检查退场的测试景进入落地页时，也需要实际内容。

## 按阅读任务选择进度

| 读者任务                     | 设计选择               | 预期行为                           |
| ---------------------------- | ---------------------- | ---------------------------------- |
| 自行控制长段文字的阅读速度   | 滚动与位置驱动的区间   | 停手保持，反向恢复对应内容         |
| 在对象经过阅读位置时注意到它 | 对象相对视口的进度     | 状态跟随该对象经过视口的位置       |
| 用手势切换短章节             | 拖拽与场景入场序列     | 提交切换后，未完成的元素动画继续   |
| 看到一次标题揭示             | 可见条件触发的时间动画 | 明确返回时是否重播                 |
| 观察缓慢移动的照片或循环文字 | 自主时间来源           | 提供能暂停实际运动的控件           |
| 对比两张已对齐的图片         | 原生 range 控件        | 指针和键盘调整分界，操作不切换场景 |

保持画面位置与跟随滚动分别定义位置和进度。需要两者时，分别说明它们的作用。翻页时长、元素时序和媒体播放时长各有用途。

原作 [Kinetic Drag](https://mocubix.renocrypt.com/lexicon/kinetic-drag/) 展示横向图片内容的惯性，其衰减设置不是 Cineview 的分页设置。目标实现的释放规则需要单独核对。

## 保留原作的内容关系

[Mocubix Lexicon](https://mocubix.renocrypt.com/lexicon/) 的这些示例说明了效果背后的设计取舍。Cineview 应用属于适配，组件只提供原作编排的一部分。

| 原作示例                                                                                      | 需要保留的细节                               | 落地页应用                                         |
| --------------------------------------------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------- |
| [Word Scrub](https://mocubix.renocrypt.com/lexicon/word-scrub/)                               | 相邻词区间重叠，选定的词带出对应图版         | 定义词与图的语义配对及共同区间，包括整句停留和退场 |
| [Horizontal Scroll Section](https://mocubix.renocrypt.com/lexicon/horizontal-scroll-section/) | 移动距离来自实际溢出，说明与素材内容对齐     | 测量最终布局，让每条说明对应其主体                 |
| [Sticky Stacking Cards](https://mocubix.renocrypt.com/lexicon/sticky-stacking-cards/)         | 卡片到达、名称和表面细节共同编排             | 保留早先卡片累积的关系，让标签始终对应正确卡片     |
| [Depth of Field](https://mocubix.renocrypt.com/lexicon/depth-of-field/)                       | 只有中央进度区间保持清晰                     | 定义阅读位置，普通模糊到清晰入场仅表达另一种行为   |
| [Ken Burns](https://mocubix.renocrypt.com/lexicon/ken-burns/)                                 | 焦点和裁切围绕照片主体，缓慢移动通过叠化重叠 | 为每张图安排焦点与观察时长，让说明和暂停共同工作   |
| [Threshold Flip](https://mocubix.renocrypt.com/lexicon/threshold-flip/)                       | 每张画提供独立的完整配色                     | 一起定义背景、正文和强调色，再安排短主题过渡       |

连续[配色插值](https://mocubix.renocrypt.com/lexicon/token-interpolation/)要保留各颜色角色的关系。分别设计的场景配色可以离散切换。检查整个过渡的对比度，把动画继承变量限制在实际需要它的最小容器内。

## 根据真实素材组合

使用最终图片选择裁切与焦点。[渐进模糊](https://mocubix.renocrypt.com/lexicon/progressive-blur/)安排在安静区域，让主体保持可见。预留图片尺寸，加载时使用保留构图的占位图。比较图片需要先对齐，再加入分界控件。

为每个动画属性指定对象和进度来源。观察组合的中间状态：两个透明度效果可以产生不同于单个效果的阅读节奏。需要独立控制移动或裁切时，使用分别定义的容器。优先使用现有布局、效果、CSS 和原生控件；框架扩展应对应明确缺失的能力。

保留可选择的语义文本。移动文字的副本应排除出屏幕阅读与键盘顺序。页面自有 CSS 动画与框架动画同时存在时，暂停控件需要覆盖两者。减少动态效果时，提供完整段落、有用图片和可用控件。

## 写出具体时序

一段短拖拽章节可以解释图片中的两个细节。图片与正文从开始就可读。以下是这段局部入场时间的设计示例：

| 对象              | 区间        | 内容关系           | 完成状态 |
| ----------------- | ----------- | ------------------ | -------- |
| 短标题            | 0–950ms     | 提出观察点         | 保持可读 |
| 标注 A 与其短说明 | 850–1450ms  | 两者共同指出细节 A | 两者保留 |
| 标注 B 与其短说明 | 1300–1900ms | 两者共同指出细节 B | 两者保留 |

A 与标题重叠 100ms，B 与 A 重叠 150ms。1900ms 后保留完整构图，等待读者离开。使用目标版本支持的时序接口表达这些区间。

这段局部时间的 0% 时，图片与正文可读；25% 时标题正在进入；50% 时标题完成、A 开始；75% 时 A 接近完成、B 正在进入；100% 时全部完成。这些百分比表示元素时间，不表示翻页距离。离场与取消需要单独定义。

## 实验中的 v2 注意事项

本地 v2 开发以 [v2 公开类型](../../v2/src/types.ts)、[元素属性](../../v2/src/jsx.ts)和当前实现为准。根目录 `package.json` 仍描述已发布的 1.x 包。这些属性和效果不代表该包已经导出对应能力。

- 提交拖拽切换后，场景时间继续。需要停手保持阅读序列时，使用滚动 `zone` 或合适的位置时间线。`view` 效果跟随几何位置，包括翻页归位期间的位置变化。
- `focus(band)` 表达中央清晰区间，普通 `focus` 表达模糊到清晰的入场。`push` 提供围绕一个原点的缩放；完整 Ken Burns 仍需要移动焦点、较长观察时序、叠化和共同暂停。
- `track="x"` 测量溢出距离。`cv-stack` 和场景 `stack` 提供堆叠布局。标签、图片对齐与匹配区间仍属于页面设计。
- `after` 引用同一 Scene、同一时间来源内的入场，负偏移产生时间重叠，并计入后继自身的 delay。普通 scroll 由根元素的可见条件触发整组依赖；离屏后继也会计时，滚到它时可能已播放完。布局决定哪些元素能同时出现在画面里。参照[时序语义](../../v2/src/core/time.ts)。
- 共享动效输出与重叠 loop 项中，位移和旋转相加，缩放和透明度相乘；裁切与同名变量使用最后一项声明的值。各 loop 保留自己的周期。不重叠的 loop 仍用原生动画；重叠 loop 与共享的命名滚动区间直接合成输出。不同进度来源采用固定嵌套顺序。
- 用 `from`/`to` 或 `defineEffect` 表达受支持的属性与变量。多段或其他浏览器可插值 CSS 可使用 `keyframes(name)`，它不支持 `exit` 和 `loop`。挂载前注册自定义效果。任意 SVG 路径形变需要合适的插值实现。
- `timeline.subscribe` 报告时间动画的状态，不提供纯 `view`、`page` 或信号来源的位置值。自定义绘制需要选择对应来源，并处理入场、离场和取消。
- `on="clock"` 在 Scene 成为当前场景时开始，跟随 Stage 暂停，重入时重播。它单独求解时序和依赖，不增加滚动区长度；结构重建保留当前 clock 入场的时间起点。普通 scroll 的 enter/eye 根元素仍按可见性启动。

这些细节由[效果定义](../../v2/src/core/fx.ts)、[渲染层](../../v2/src/render/layers.ts)和[时间订阅](../../v2/src/core/timeline.ts)规定。实现改变后重新核对。

## 给 AI 一份可复用说明

第一次提出需求时，简单描述即可：

```text
我想做一个介绍软件的页面，已有三张界面截图和两段文字。
先让访客明白软件的用途，再看具体功能。
请推荐合适的呈现方式，展示开场、变化过程和完整状态。
参考 Cineview 设计指南，实现前核对目标版本。
```

AI 应把这段描述整理成下方的详细说明。先用普通语言解释推荐方案，再讨论效果名称。网站入口可以帮助整理需求，并提供指南供用户交给自己的 AI；这个方案不需要网站集成 AI 服务。

把真实内容与以下说明一起提供给 AI。字段表示设计要求，不是 Cineview 属性。

```text
依据阅读任务和真实内容设计这张 Cineview 落地页。
读者目标与关键事实：
场景内容、词与图、标签与对象的对应关系：
静态布局、图片焦点、裁切和颜色角色：
进度来源及选择理由：
入场、重叠、完整阅读停留与离场：
初始、25%、50%、75% 与完成状态：
停手、反向、取消与重入行为：
手机布局、减少动态效果、控件与暂停：
目标 Cineview 版本与权威类型：

实现前给出场景计划和属性与进度来源的对应关系。
使用现有受支持的 API、CSS 和原生控件表达计划。
说明参考设计经过哪些适配，哪些能力需要扩展。
验收结论依据实际浏览器证据。
```

## 验收阅读体验

在实际应用地址检查内容关系和完整状态：

- 在关键词或标注处停手、反向，检查对应图片。
- 提交与取消离场，再返回，检查文字、固定内容和视频连续性。
- 检查快速输入、键盘导航、适用场景的滚动条，以及需要独立手势的控件。
- 检查窄屏、横竖屏切换、图片准备状态和最终移动距离。
- 暂停自主运动，检查减少动态效果时的呈现。
- 在目标浏览器测量性能，区分原生 CSS 与脚本驱动的实际开销。

插值正确、控制台无报错和组合演示只覆盖这些行为的一部分。报告实际观察过的场景。一个代表性组合不能说明原作全部 41 项已经验收。
