# 帮用户把需求变成动画方案

[English](./design-assistant.md) · [简体中文](./design-assistant.zh-CN.md)

Cineview 的设计初衷之一，是让 AI 能理解页面的内容关系、动画用途和实现边界，并据此向使用者提供建议。普通用户可以描述想表达的内容，或直接提供 PRD。AI 负责把这些需求整理成可评估的画面与交互方案，再用当前支持的能力实现。

这份指南面向本地 2.0。它规定 AI 如何协助设计，不表示项目已经内置对话服务或自动生成器。按需阅读[41 条设计参考](./lexicon.zh-CN.md)、[落地页构图与编排](./landing-pages.zh-CN.md)和[声明与实现约定](./declarative-design.zh-CN.md)。生成代码时以 [v2 类型](../../v2/src/types.ts)、[元素属性](../../v2/src/jsx.ts)及实际驱动为准。

## 先给使用者一个能看懂的建议

用户不需要先学习效果名。先说明推荐的画面：哪些内容一开始可见，操作时哪张图变化，文字对应哪个细节，最后能读到什么。再解释这个动作为什么有助于理解内容，以及需要哪些素材。

例如，用户说“我有三张软件截图，想讲清三个功能”，可以这样建议：

> 建议让三段功能说明对应同一位置的三张截图。读到“整理资料”时显示资料列表，读到“标记重点”时切到标注细节，最后显示整理后的结果。每次先让下一张图出现，再淡去上一张，说明和图一起变化。读者停下时保留当前状态，最后三段文字仍能完整阅读。

这个建议明确了图文关系与停手行为。进一步确认素材后，再选择区间、裁切和代码。用户指定 drag、品牌色或素材风格时，保留这些约束，并说明它们对阅读节奏的影响。

推荐一个最合适的方案。只有另一种方案会明显改变阅读体验时，才补充第二种，并说清取舍。41 条参考留作 AI 的查询依据，首次答复只介绍本次有用的几条。

## 从常见需求开始

以下是设计入口，不是基于项目使用统计的排名。先按用户任务定位，再查对应编号。

| 用户的说法                     | 推荐的内容组织                                                                 | 可查参考           | 动画需要克制的地方                                               |
| ------------------------------ | ------------------------------------------------------------------------------ | ------------------ | ---------------------------------------------------------------- |
| “首屏要有张力，但要简洁”       | 用清楚的用途说明、一个主视觉和可见的主要操作建立构图；主视觉可用线条或抽象图形 | 09、30、32         | 正文与操作入口从开始就可用；挑一个主要变化，避免所有对象同时入场 |
| “把软件的几个功能讲明白”       | 每个功能说明配对应截图或线框细节，共用明确的切换区间                           | 02、03、08、10     | 截图与说明保持匹配；停手能读，快速通过也能看到完整内容           |
| “让人看懂一个流程”             | 按步骤展示状态变化，保留此前步骤或清楚显示当前步骤                             | 06、09、11         | 连接线表示真实顺序；同一时刻只强调当前需要解释的部分             |
| “展示处理前后的区别”           | 对齐两张图，提供可拖动分界和明确标签                                           | 31                 | 比较是用户操作，不自动往返；保留键盘控制与主体对齐               |
| “这张宽图需要分段解释”         | 用真实溢出距离浏览宽图，在主体经过时出现对应说明                               | 05、08             | 先测量裁切与终点；窄屏可改为分段图片，不能只缩小整幅图           |
| “让读者理解数据与结果”         | 先展示数值、单位和依据，再用计数或图形解释变化                                 | 09、13             | 只用已提供的数据；关键数值有静态完成态，不反复重播妨碍比较       |
| “展示作品或一组图片”           | 先安排图片顺序、焦点和标题，再选择逐项浏览、卡片或缓慢观察                     | 06、14、25、26、27 | 观察原图时保留暂停；颜色处理需要适合素材，不能遮掉关键细节       |
| “把长 PRD、研究或文章做成页面” | 按论点分段，图随对应文字解释，目录显示当前位置                                 | 01、02、10、23     | 大段内容优先让读者控制速度；正文、目录和引用始终可用             |
| “做发布或活动页面，让人报名”   | 先显示活动内容、时间和主要操作，再用章节介绍亮点与证据                         | 11、16、17、41     | 时间、价格和报名入口不等待动画；导航要说明当前位置和首尾状态     |

## 按意图查阅 41 条参考

从“解释关系、安排浏览、处理素材、强调文字、组织颜色”中选择与当前问题有关的类别，再到[完整索引](./lexicon.zh-CN.md)查询。每条都提供原作链接、设计用途与 2.0 的实现入口或限制。

参考原作时，提取内容之间的关系：哪个词对应哪张图，卡片为何累积，主体为什么在此处清晰，颜色如何保持角色。把这些关系换成用户的实际内容。仅复用一个模糊、位移或渐显，并不能保留完整的设计意图。

向用户说明所选参考的作用。例如：“采用 03 的阅读控制与 08 的图文联动，让说明和截图共用进度。”同时标明需要页面自己编排的部分。41 条包含布局、交互、浏览器能力和素材处理，不能统一作为 `fx` 名称使用。

## 收到 PRD 后先提取什么

先读完整 PRD，再建立需求与画面的对应关系。保留事实、已有交互和约束；缺失的信息注明假设。数值、客户评价、产品能力和素材不得凭空补齐。

| 从 PRD 提取                        | 转成设计决定                                       |
| ---------------------------------- | -------------------------------------------------- |
| 目标用户、进入页面的原因、主要操作 | 第一屏必须交代的用途，以及操作入口的位置           |
| 核心事实、功能顺序、依赖关系       | 场景顺序；哪些内容需要同时比较，哪些需要按先后解释 |
| 已有文字、图片、视频、SVG、图表    | 每个素材的用途、裁切、替代文字、标签与对应说明     |
| 内容量、浏览设备、已有导航或手势   | scroll 或 drag；普通段落、锁定区或独立可操作区域   |
| 品牌、排版、语言、动态偏好         | 静态完成构图；翻译变长时的布局；需要减少的动态     |
| 加载、暂停、返回、表单和无障碍要求 | 动画中断与完成态；媒体与控件的实际行为             |

影响方案的必要信息缺失时，先问最关键的问题。例如，PRD 只有功能名却要求截图联动，需要确认是否有对应素材。时长和缓动通常由 AI 先提出设计值，不要求普通用户填写。

## 从需求推导分镜

1. 为每景写一句读者需要理解的事实，并关联 PRD 的需求编号。区分事实说明、证明材料和主要操作。
2. 先画完整可读的静态构图。确定图文配对、视觉层级、裁切和颜色，再设计初始状态。
3. 为主要变化写明目的。需要并排比较的内容同时保留；依赖前一步的内容按顺序出现。纯装饰动作从属于这项任务。
4. 选择进度来源。长说明或精确图文对应适合 scroll 的位置进度；短章节可使用 drag。已有输入要求优先保留。把保持画面位置与推进动画分别说明。
5. 写出入场、完整阅读停留、切换与退场。指定下一张图何时出现、上一张图何时消失，避免两者同时不可见。
6. 定义停手、反向、取消、重入、快速通过、加载失败和减少动态效果时的状态。中英文与窄屏都检查完整构图。
7. 将分镜映射到当前可用的组件、属性、CSS 或页面控件。写明需要扩展的能力及最小替代方案，再进入实现。

交付给使用者的分镜至少包含下列信息。这些是设计字段，不是 Cineview 属性：

```text
需求编号与读者要理解的事实：
场景与素材：
初始构图和完整可读的构图：
图、词、标注及对象之间的对应关系：
主要变化、原因与参考编号：
输入方式、进度来源和区间含义：
入场、切换、阅读停留与退场：
停手、反向、取消、重入及快速通过：
窄屏、中英文、减少动态效果和加载失败：
2.0 实现入口、限制与待扩展部分：
浏览器中要检查的结果：
```

## 示例：把软件介绍 PRD 变成分镜

假设 PRD 要求介绍“收集资料、标记重点、生成说明”三个步骤。已有三张对应的 SVG 线框图；主要操作是“开始使用”；品牌色与中英文文案已给定。这里的功能与区间用于演示设计方法，不是 Cineview 的产品能力或默认参数。

| 需求                           | 场景方案                                                    | 主要变化与理由                                        | 2.0 实现方向                                                            |
| ------------------------------ | ----------------------------------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------------------- |
| R1：先明白工具用途并能开始使用 | Hero 显示用途说明、主要操作与一张静态全流程线框图           | 装饰连接线按流程方向绘出，文字与操作保持可用；参考 09 | 普通 scroll 段落，局部 `draw` 入场；布局与核心文字保持静态              |
| R2：看懂三个步骤及其结果       | 一个说明区，左侧保留步骤文字，右侧在固定位置呈现对应 SVG 图 | 用共享进度切换图与当前步骤强调；参考 03、08、30       | Scene `zone` 安排阅读区间；同 Scene 的时间类动画与页面 CSS 管理图文切换 |
| R3：决定是否开始使用           | 显示三步总结和主要操作                                      | 完整内容保持；读者离开说明区后自然进入操作区          | 普通静态区；按钮保持普通交互                                            |

R2 的进度表示该说明区的局部阅读进度，不是整页滚动比例，也不是 drag 的页面位移。下列百分比是分镜草案；实现时按文字量与布局调整，核对求解后的总时长。scroll zone 中 1ms 对应 1px 的滚动距离，不能直接照搬计时动画的毫秒值。

| 局部进度    | 图与文字的状态                                                  |
| ----------- | --------------------------------------------------------------- |
| 0% 至 10%   | 图 A 展示资料列表，第一步强调；标题和三步文字可读               |
| 10% 至 30%  | 保持图 A，让读者看清资料如何收集                                |
| 30% 至 40%  | 图 B 与第二步强调一起出现，再淡去图 A；裁切与标注仍指向同一主体 |
| 40% 至 65%  | 保持图 B，突出标注细节；第一步文字仍在                          |
| 65% 至 75%  | 图 C 与第三步强调一起出现，再淡去图 B                           |
| 75% 至 100% | 保持输出结果图 C 和全部步骤文字；完整状态持续到离开说明区       |

0%、25%、50%、75% 和 100% 分别应能看见 A、A、B、C、C，以及匹配的步骤强调。三个图文切换状态由同一局部进度决定。反向通过区间时按相反顺序恢复，停手保持当前画面。减少动态效果时改为三组图文顺序排列，保留相同事实与操作。

Hero 的线条逐笔绘出是短暂入场；R2 的图文切换用于读者控制阅读，两者不必共用时钟。若 PRD 指定 drag，改为短章节并单独安排每景入场：提交后元素时间会继续，不能承诺松手就停在截图切换中间。不要通过修改分页手势来补偿内容过长。

## 为设计元素分配具体动作

| 元素                 | 先决定什么                           | 合适的变化与检查                                                |
| -------------------- | ------------------------------------ | --------------------------------------------------------------- |
| 标题、正文、主要操作 | 信息层级和完整可读状态               | 标题可短暂揭示；长正文避免逐字等待；主要操作从开始就可用        |
| 截图与图片           | 主体、焦点、比例和对应文字           | 先对齐再切换；标注与图共用区间；加载占位保留尺寸与构图          |
| SVG 线条与抽象图形   | 线条是否解释连接、顺序或范围         | 绘制方向遵循语义；装饰不压过正文；`draw` 不提供任意路径形变     |
| 标签、箭头、图例     | 它解释哪个对象，以及何时成立         | 与对象同时出现和退出；避免对象换了但标签还保留上一项            |
| 卡片与列表           | 顺序表示步骤、时间还是并列关系       | 累积步骤可堆叠；需要同时比较时保留并列视图                      |
| 数值与图表           | 单位、数据来源和比较基准             | 先保证数值正确；动画保留标尺与标签；减少动态时显示最终值        |
| 背景与品牌色         | 背景、正文、强调色的角色             | 完整配色一起检查；过渡中也要可读；动画变量限制到需要的容器      |
| 视频与自主循环       | 视频说明什么、何时暂停或交还原生播放 | 检查首帧、离开、取消与重入；页面自有 CSS 动画也接入实际暂停控制 |

## 落实到当前 2.0 能力

设计建议与实现状态分开记录。先查[41 条索引](./lexicon.zh-CN.md)的实现入口，再核对[声明约定](./declarative-design.zh-CN.md)。

- `after` 引用同一 Scene、同一时间来源内的入场。普通 scroll 由根元素启动整组依赖，包含离屏后继。负偏移产生时间重叠，布局决定能否同时看见。
- 重叠 loop 项按动效规则加乘，并保留各自周期；裁切与同名变量仍由后声明者覆盖。不重叠 loop 继续用原生动画，重叠输出直接合成。
- `on="clock"` 从 Scene 成为当前场景时开始，跟随 Stage 暂停，重入时重播，不增加滚动距离。依赖保持在该 clock 时间内；结构重建保留当前播放进度。
- `timeline.subscribe` 提供时间类帧，不是获取任意 view/page/signal 位置的通用接口。SVG 或 canvas 必须使用实际需要的来源，并处理取消与销毁。
- 具名逗号 `threshold` 仍是待实现提议。原生横向惯性滚动、无限循环浏览也不能用有限场景的 drag 分页冒充。

先解决静态布局、素材与内容编排。只有当前能力确实缺失，才讨论框架扩展。一个预设可用，不代表完整参考方案已实现；可解析也不等于已经有实际驱动。

## 让案例与验收回答同一个问题

案例正文写明读者任务、素材关系、所选参考和适配内容，并附初始、中间和完成画面。代码说明对应的输入和来源，另列页面自定义部分。标明实际测试过的浏览器与操作，保留未验证项。

R2 的验收应检查：每个区间是否图文匹配，快速越过两个切换区间后是否仍显示当前图，反向与停手是否恢复正确状态，加载未完成时是否保留有用内容，以及中英文和窄屏下是否仍能读完。场景退场后，下一景必须有实际内容。

用户确认设计时应能看懂画面与取舍；开发者验收时应能对照同一组状态检查实现。演示页的功能与参考编号需要逐项说明，避免让一个组合演示承担全部 41 条的验收结论。
