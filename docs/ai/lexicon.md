# 41 design references and their 2.0 implementation routes

[English](./lexicon.md) · [简体中文](./lexicon.zh-CN.md)

Select references for the content. Use the [requirements and PRD guide](./design-assistant.md) to establish the reader's task, then consult the relevant entries here. Explain the screen and tradeoffs to the user rather than asking them to choose among 41 names.

Numbers, English names, and original links follow the 41 entries in [Mocubix Lexicon](https://mocubix.renocrypt.com/lexicon/). The purposes and Cineview mappings are this project's design recommendations, not claims that the local implementation reproduces the original. Check original assets, complete choreography, and browser requirements separately.

## How to use this index

Look up the reading task, the content relationship to preserve, and the 2.0 implementation route. Choose one main purpose for motion in each scene, then add supporting actions justified by the content. The [landing-page guide](./landing-pages.md) explains readable states and asset relationships.

There are three implementation routes. None means browser acceptance is complete:

- Framework primitive: a related component, source, or preset exists; the page still supplies composition and timing.
- Page implementation: page CSS, native controls, asset processing, or local logic supplies the behavior; it is not another Cineview preset.
- Extension needed: the corresponding framework capability is absent or lacks a driver; explain the limit before choosing an alternative or an explicit extension.

Check browser CSS features in the target environment. This table promises no browser versions. `on="clock"` runs from current-Scene entry and follows Stage pause. `keyframes(name)` cannot be used in `exit` or `loop`. See [implementation limits](#implementation-limits-and-source) for native scroll versus drag pagination.

## Implementation limits and source

Check sources and presets in [effect definitions](../../src/core/fx.ts), structure and attributes in [JSX interfaces](../../src/jsx.ts), and navigation in [public interfaces](../../src/types.ts) and [Stage](../../src/elements/stage.ts). Check [time solving](../../src/core/time.ts) and [rendering layers](../../src/render/layers.ts) for timing and composition. These implementations determine runnable code; an original reference name cannot replace that check.

Drag pagination, scroll document progress, and local native scrollers have different progress and gesture behavior. Check nested controls with pointer, keyboard, and mobile input. `on="clock"` supplies Scene-entry time and follows Stage pause; page-owned movement still needs its own pause and cleanup handling.

For each implementation, record the task, the original relationships retained, page-owned work, and actual acceptance. Recommendations can combine ideas from several entries, explaining each role and checking middle states, stopping, reverse input, cancellation, return, and reduced motion. Original performance claims are not Cineview performance results.
